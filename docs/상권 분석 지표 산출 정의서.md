# 1. 문서 개요

이 문서는 상권 탐색 서비스에서 사용하는 주요 데이터와 파생 지표의 정의, 산식, 정규화 방식, 비교 기준, 구현 제약을 하나의 기준으로 정리한 문서다.

대상 독자는 다음과 같다.

- **기획자**: 화면에 표시되는 값이 어떤 기준으로 만들어지는지 확인
- **개발자**: DB 조회와 서비스 로직 구현 기준 확인
- **데이터 분석 담당자**: 지표 정의와 정규화 방식 검토
- **발표/평가자**: 서비스 점수의 근거와 한계 이해

핵심 원칙은 다음과 같다.

1. 실제 DB에서 직접 조회할 수 있는 값과 계산이 필요한 파생 값을 구분한다.
2. 동일한 지표는 모든 화면에서 하나의 계산 결과를 재사용한다.
3. 비교 지표는 원칙적으로 **동일 분기 + 동일 업종의 상권 집단**을 기준으로 산출한다.
4. 경쟁 여건은 동일 분기·동일 업종의 점포 수, 점포당 거래건수, 폐업률을 이용해 상대 비교한다.
5. 모든 핵심 점수는 최종적으로 **높을수록 긍정적**인 방향으로 통일한다.

즉 업종 특성과 시점 차이를 최대한 제거한 상태에서 상권을 비교한다.

### 정의

특정 분기·상권·업종에서 발생한 전체 매출 규모다.


### 해석

## 4.3 QoQ 매출 성장률

### 정의

현재 분기 매출이 직전 분기 대비 얼마나 증가 또는 감소했는지를 나타낸다.

### 산식

```text
                         현재 분기 매출 - 이전 분기 매출
매출 성장률(%) = ───────────────────────────────── × 100
                                이전 분기 매출

GrowthRate
= (CurrentSales - PreviousSales)
  / PreviousSales
  × 100
```

### 예외 처리

- 전분기 데이터 없음 → `NULL`
- 전분기 매출이 0 → `NULL`
- 전분기 매출 > 0, 현재 매출 = 0 → `-100%`

### 주의

동일한 `qoq_growth_rate` 값을 KPI, Ranking, Compare, Why Explore, Exploration Score에서 함께 사용해야 한다.

현재 Mock처럼 성수동 성장률이 `8.2%`와 `12.4%`로 동시에 존재하면 안 된다.

## 4.4 성장 점수

### 정의

QoQ 매출 성장률을 동일 업종 내 상권끼리 비교할 수 있도록 0~100점으로 정규화한 값이다.

### 왜 단순 Min-Max를 쓰지 않는가

성장률은 낮은 기저효과 때문에 일부 상권이 매우 큰 양수 값을 가질 수 있다. 이 경우 단순 Min-Max를 사용하면 대부분 상권의 점수가 비슷하게 압축될 수 있다.

따라서 **5th percentile~95th percentile 범위로 극단값을 제한한 뒤 Min-Max 정규화**한다.

### 1단계: Winsorizing [1]

```text
ClippedGrowth
= clip(GrowthRate, P5, P95)
```

### 2단계: 0~100 정규화

```text
                 ClippedGrowth - P5
GrowthScore = ─────────────────────── × 100
                       P95 - P5
```

### 해석

- 100에 가까움 → 동일 업종 대비 성장성이 매우 높음
- 50 전후 → 비교군 중 중간 수준
- 0에 가까움 → 성장성이 낮음

[1] **Winsorizing**: 극단값이 전체 분포를 과도하게 왜곡하지 않도록 일정 기준을 벗어난 값을 경계값으로 제한하는 방식. 본 문서에서는 성장률을 하위 5%~상위 95% 범위로 제한한다.

## 4.5 거래 활성도 점수

### 정의

현재 분기 거래건수의 규모가 동일 업종의 다른 상권에 비해 얼마나 큰지를 나타낸다.

이 지표는 **거래 성장률이 아니라 현재 거래 규모**를 평가한다.

### 1단계: 로그 변환

```text
LogTransaction
= ln(1 + Transaction)
```

### 2단계: Min-Max 정규화

```text
                       LogTransaction - LogTransactionMin
TransactionScore = ───────────────────────────────────────── × 100
                       LogTransactionMax - LogTransactionMin
```

즉,

```text
                    ln(1 + Transaction) - ln(1 + TransactionMin)
TransactionScore = ─────────────────────────────────────────────── × 100
                    ln(1 + TransactionMax) - ln(1 + TransactionMin)
```

### 왜 로그를 사용하는가

거래건수는 초대형 상권과 일반 상권의 차이가 매우 클 수 있다. 로그 변환은 이 차이를 완화해 상권 간 상대 비교를 더 안정적으로 만든다.

### 해석

높을수록 거래가 활발한 상권이다.

## 4.6 경쟁 점수 (CompetitionScore)

### 정의

동일 업종의 점포 수, 점포당 거래건수, 폐업률을 이용해 상권의 경쟁 여건을 비교하는 점수다.

점수가 높을수록 경쟁 여건이 상대적으로 양호하다는 의미다. 사용자가 바로 이해할 수 있도록 점포 공급, 점포당 수요, 폐업 위험의 세 가지 지표만 사용한다.

### 구성

```text
CompetitionScore
= StoreCountScore       × 0.50
+ DemandPerStoreScore   × 0.30
+ ClosingRateScore      × 0.20
```

세 구성요소는 모두 경쟁 여건이 상대적으로 양호할수록 높은 점수가 되도록 정규화한다.
즉, 동일 업종 점포 수가 적고, 점포당 거래건수가 많으며, 폐업률이 낮을수록 점수가 높다.

### 4.6.1 점포 수 점수 StoreCountScore — 50%

#### 원천 데이터

```text
StoreCount = similr_induty_stor_co
```

같은 분기·같은 업종·같은 상권의 동일 업종 점포 수를 사용한다.

#### 정규화

동일 분기·동일 업종의 상권 집단 내에서 점포 수를 Min-Max 정규화한 뒤 방향을 반전한다.

```text
StoreCountScore
= (1 - Norm(StoreCount)) × 100
```

#### 해석

같은 업종 점포 수가 적을수록 경쟁 공급이 적다고 보고 높은 점수를 부여한다.

### 4.6.2 점포당 거래건수 점수 DemandPerStoreScore — 30%

#### 산식

```text
DemandPerStore
= TransactionCount / StoreCount
```

점포 수가 0이면 `NULL` 처리한다.

#### 정규화

동일 분기·동일 업종의 상권 집단 내에서 점포당 거래건수를 Min-Max 정규화한다.

```text
DemandPerStoreScore
= Norm(DemandPerStore) × 100
```

#### 해석

점포 하나당 거래건수가 많을수록 해당 업종의 수요가 점포에 충분히 분산·유입된다고 보고 높은 점수를 부여한다.

### 4.6.3 폐업률 점수 ClosingRateScore — 20%

#### 원천 데이터

```text
ClosingRate = clsbiz_rt
```

#### 정규화

동일 분기·동일 업종의 상권 집단 내에서 폐업률을 Min-Max 정규화한 뒤 방향을 반전한다.

```text
ClosingRateScore
= (1 - Norm(ClosingRate)) × 100
```

### 해석

폐업률이 낮을수록 해당 업종의 운영 안정성이 높고 경쟁 여건이 상대적으로 양호하다고 해석한다.

### 한계

`CompetitionScore`는 경쟁 업체의 질, 매출 규모, 임대료, 브랜드 경쟁력 등을 직접 측정하지 않는 상대 비교 점수다. 다음 요인의 영향을 받을 수 있다.

- 점포 규모와 매장별 매출 차이
- 업종별 거래건수 구조
- 개업·폐업 신고 시점과 실제 영업 상태의 차이
- 관광객 비중 및 이벤트성 소비
- 경기 변동

내부 데이터 필드명은 `competition_score`를 유지하고, 사용자 화면에서는 **경쟁 여건**으로 표시한다. 점수는 동일 분기·동일 업종 내 상권 간 상대 비교 결과다.

## 4.7 최종 탐색 점수

### 정의

상권의 성장성, 거래 활성도, 시장 압력 안정성을 종합한 0~100점 점수다.

### 산식

```text
ExplorationScore
= GrowthScore         × 0.40
+ TransactionScore    × 0.35
+ CompetitionScore    × 0.25
```

### 예시

- GrowthScore = 91
- TransactionScore = 85
- CompetitionScore = 62

```text
ExplorationScore
= 91 × 0.40
+ 85 × 0.35
+ 62 × 0.25
= 81.65
```

화면 표시값은 반올림하여 `82점`으로 표현할 수 있다.

### 방향성

모든 하위 점수는 높은 값이 긍정적인 의미를 가지므로 단순 가중합이 가능하다.

# 5. Benchmark Percentile 및 순위 산정

## 5.1 Percentile 정의

사용자에게는 다음과 같이 표현한다.

```text
상위 N%
```

예:

- `5` → 상위 5%
- `18` → 상위 18%
- `38` → 상위 38%

따라서 percentile 값은 **낮을수록 상위권**이다.

## 5.2 비교 대상

항상 동일한:

- 분기
- 업종

의 상권 집단을 비교한다.

## 5.3 대상 지표

- Sales Percentile
- Growth Percentile
- Transaction Volume Percentile
- Competition Percentile

## 5.4 산정 방법

내림차순 rank를 기준으로 상위 비율을 계산한다. **구현 기준(확정)**:

```text
                     내림차순 Rank
TopPercentile = ───────────────────── × 100
                  비교 대상 수(N)
```

값이 작을수록 상위권이다 (예: `TopPercentile = 3` → 상위 3%).

- 동점 처리: `RANK()`/`rank(method="min")` 방식 — 동일 값은 동일 순위를 받고, 다음 순위는 동점 개수만큼 건너뛴다.
- pandas 구현: `series.rank(method="min", pct=True, ascending=False) * 100` — `pct=True`는 정확히 `rank / N`을 의미하므로 위 공식과 동일하다.
- SQL 구현: `RANK() OVER (...) / COUNT(*) OVER () * 100`.
- **주의**: PostgreSQL의 `PERCENT_RANK()`는 `(rank - 1) / (N - 1)`로 위 공식과 다른 값을 낸다. 두 코드 경로(analytics 점수 파이프라인, `/sales/summary` 엔드포인트)가 서로 다른 산식을 쓰다 발견되어 전부 `RANK() / N × 100` 기준으로 통일했다. `PERCENT_RANK()`는 이 문서의 percentile 정의에는 사용하지 않는다.

### 5.5 서울 종합 순위 (`seoul_rank`)

`seoul_rank`는 동일 분기 및 동일 업종에 속한 서울 전체 상권을 대상으로, 주요 Benchmark 지표에서 전반적으로 우수한 상권을 판단하기 위한 종합 순위다.

종합 순위 산정에는 다음 4개 Percentile을 사용한다.

- Sales Percentile
- Growth Percentile
- Transaction Volume Percentile
- Competition Percentile

각 Percentile은 값이 낮을수록 상위권을 의미하므로, 4개 Percentile의 평균값을 종합 Benchmark 값으로 사용한다.

```text
OverallBenchmarkPercentile
= (
    SalesPercentile
    + GrowthPercentile
    + TransactionVolumePercentile
    + CompetitionPercentile
  ) / 4
```

`OverallBenchmarkPercentile`이 낮은 상권부터 순위를 부여한다.

```text
seoul_rank
= Rank(
    OverallBenchmarkPercentile,
    ascending=True
  )
```

비교 대상은 항상 동일한 분기(`stdr_yyqu_cd`)와 동일한 업종(`svc_induty_cd`)에 속한 서울 전체 상권으로 제한한다.

동점인 경우 `rank(method="min")` 방식을 적용한다.

예를 들어 다음과 같은 경우:

```text
상권 A
Sales Percentile              = 5
Growth Percentile             = 8
Transaction Volume Percentile = 4
Competition Percentile        = 7

OverallBenchmarkPercentile
= (5 + 8 + 4 + 7) / 4
= 6
```

동일 분기·동일 업종 내에서 이 값이 가장 낮다면 `seoul_rank = 1`이 된다.

따라서 `seoul_rank = 1`은 매출, 성장성, 거래 활성도, 시장 부담 측면에서 종합적으로 가장 상위권에 위치한 상권을 의미한다.

# 8. Insight / Warning 생성 기준

Insight와 Warning은 원천 데이터가 아니라 **계산된 지표 조합을 문장으로 변환한 규칙 기반 결과**다.

```text
GrowthScore >= 70
AND TransactionScore >= 70
```

출력:

> 성장성과 거래 활성도는 높지만 경쟁 여건이 좋지 않은 상권입니다.

다른 예:

```text
GrowthScore >= 70
AND TransactionScore < 70
AND CompetitionScore >= 70
```

출력:

> 성장세가 우수하고 시장 압력은 비교적 안정적이나 현재 거래 규모는 중간 수준입니다.

Insight/Warning은 LLM 자유 생성보다 초기에는 템플릿 기반이 일관성과 검증 측면에서 유리하다.

# 10. 현재 데이터의 한계 및 제약사항

## 10.1 연령 × 성별 교차 데이터 없음

현재 DB에는:

- 연령별 매출
- 전체 남성 매출
- 전체 여성 매출

만 있다.

따라서 `20대 여성`, `30대 남성`처럼 연령과 성별을 결합한 실제 비율은 계산할 수 없다.

표현 예:

```text
주요 연령층: 20대 45%
주요 성별: 여성 61%
```

## 10.2 CompetitionScore의 해석 및 제약

CompetitionScore는 다음 세 가지 지표를 이용한 상대 비교 점수다.

```text
CompetitionScore
= StoreCountScore       × 0.50
+ DemandPerStoreScore   × 0.30
+ ClosingRateScore      × 0.20
```

높을수록 같은 업종 점포가 적고, 점포당 거래가 많으며, 폐업률이 낮아 경쟁 여건이 상대적으로 양호하다는 의미다.

다만 실제 경쟁 업체의 규모·브랜드력·임대료·상품 차별성까지 측정하는 직접 경쟁도는 아니다. 사용자 화면에서는 `경쟁 여건`으로 표시한다.

## 10.3 Mock 값과 실제 산식 결과 불일치 가능

# 12. Python 구현 예시

아래 코드는 PostgreSQL 조회 결과를 `pandas.DataFrame`으로 가져왔다는 가정으로 작성한다.

```python
import numpy as np
import pandas as pd


GROUP_KEYS = ["stdr_yyqu_cd", "trdar_cd", "svc_induty_cd"]
COMPARE_KEYS = ["stdr_yyqu_cd", "svc_induty_cd"]
SERIES_KEYS = ["trdar_cd", "svc_induty_cd"]

BENCHMARK_PERCENTILE_COLUMNS = [
    "sales_percentile",
    "growth_percentile",
    "volume_percentile",
    "competition_percentile",
]


def safe_minmax(series: pd.Series, neutral: float = 0.5) -> pd.Series:
    """Series를 0~1로 Min-Max 정규화한다."""
    valid = series.dropna()

    if valid.empty:
        return pd.Series(np.nan, index=series.index)

    min_value = valid.min()
    max_value = valid.max()

    if min_value == max_value:
        result = pd.Series(neutral, index=series.index, dtype=float)
        result[series.isna()] = np.nan
        return result

    return (series - min_value) / (max_value - min_value)


def aggregate_sales(df: pd.DataFrame) -> pd.DataFrame:
    """분기 × 상권 × 업종 단위로 매출과 거래건수를 집계한다."""
    return (
        df.groupby(GROUP_KEYS, as_index=False)
        .agg(
            sales=("thsmon_selng_amt", "sum"),
            transaction_count=("thsmon_selng_co", "sum"),
        )
    )


def add_qoq_growth(df: pd.DataFrame) -> pd.DataFrame:
    """QoQ 매출 성장률과 QoQ 거래건수 성장률을 계산한다."""
    result = df.copy()

    result = result.sort_values(
        ["trdar_cd", "svc_induty_cd", "stdr_yyqu_cd"]
    )

    result["previous_sales"] = (
        result.groupby(SERIES_KEYS)["sales"].shift(1)
    )
    result["previous_transaction_count"] = (
        result.groupby(SERIES_KEYS)["transaction_count"].shift(1)
    )

    result["growth_rate"] = np.where(
        result["previous_sales"] > 0,
        (
            (result["sales"] - result["previous_sales"])
            / result["previous_sales"]
            * 100
        ),
        np.nan,
    )

    result["transaction_growth"] = np.where(
        result["previous_transaction_count"] > 0,
        (
            (
                result["transaction_count"]
                - result["previous_transaction_count"]
            )
            / result["previous_transaction_count"]
            * 100
        ),
        np.nan,
    )

    return result


def growth_score(series: pd.Series) -> pd.Series:
    """성장률을 P5~P95로 제한한 후 0~100점으로 변환한다."""
    valid = series.dropna()

    if valid.empty:
        return pd.Series(np.nan, index=series.index)

    p5 = valid.quantile(0.05)
    p95 = valid.quantile(0.95)

    if p5 == p95:
        result = pd.Series(50.0, index=series.index)
        result[series.isna()] = np.nan
        return result

    clipped = series.clip(lower=p5, upper=p95)
    return ((clipped - p5) / (p95 - p5) * 100).clip(0, 100)


def transaction_score(series: pd.Series) -> pd.Series:
    """거래건수를 log1p 변환 후 0~100점으로 정규화한다."""
    log_values = np.log1p(series.clip(lower=0))
    return safe_minmax(log_values) * 100


def add_average_ticket(df: pd.DataFrame) -> pd.DataFrame:
    """평균 객단가를 계산한다."""
    result = df.copy()
    result["avg_ticket"] = (
        result["sales"]
        / result["transaction_count"].replace(0, np.nan)
    )
    return result


def store_count_score(series: pd.Series) -> pd.Series:
    """동일 비교군 내 점포 수가 적을수록 높은 점수를 부여한다."""
    return (1 - safe_minmax(series)) * 100


def demand_per_store_score(series: pd.Series) -> pd.Series:
    """동일 비교군 내 점포당 거래건수가 많을수록 높은 점수를 부여한다."""
    return safe_minmax(series) * 100


def closing_rate_score(series: pd.Series) -> pd.Series:
    """동일 비교군 내 폐업률이 낮을수록 높은 점수를 부여한다."""
    return (1 - safe_minmax(series)) * 100


def competition_score(
    store_count: pd.Series,
    demand_per_store: pd.Series,
    closing_rate: pd.Series,
) -> pd.Series:
    """점포 수·점포당 거래건수·폐업률 기반 경쟁 점수를 계산한다."""
    return (
        store_count * 0.50
        + demand_per_store * 0.30
        + closing_rate * 0.20
    )


def exploration_score(
    growth: pd.Series,
    transaction: pd.Series,
    competition: pd.Series,
) -> pd.Series:
    """최종 탐색 점수를 계산한다."""
    return (
        growth * 0.40
        + transaction * 0.35
        + competition * 0.25
    )


def add_percentile_and_rank(
    df: pd.DataFrame,
    value_col: str,
    prefix: str,
) -> pd.DataFrame:
    """동일 분기·동일 업종 내 rank와 '상위 N%' percentile을 계산한다."""
    result = df.copy()

    result[f"{prefix}_rank"] = (
        result.groupby(COMPARE_KEYS)[value_col]
        .rank(method="min", ascending=False)
    )

    result[f"{prefix}_percentile"] = (
        result.groupby(COMPARE_KEYS)[value_col]
        .rank(method="min", pct=True, ascending=False)
        * 100
    )

    return result


def add_seoul_rank(
    df: pd.DataFrame,
    percentile_cols: list[str] = BENCHMARK_PERCENTILE_COLUMNS,
) -> pd.DataFrame:
    """Benchmark Percentile 평균을 기반으로 서울 종합 순위를 계산한다."""
    result = df.copy()

    result["overall_benchmark_percentile"] = (
        result[percentile_cols]
        .mean(axis=1, skipna=False)
    )

    result["seoul_rank"] = (
        result.groupby(COMPARE_KEYS)["overall_benchmark_percentile"]
        .rank(method="min", ascending=True)
    )

    return result


def calculate_time_patterns(df: pd.DataFrame) -> pd.DataFrame:
    """시간대별 매출 비중과 피크 시간대를 계산한다."""
    result = df.copy()

    columns = {
        "00-06시": "tmzon_00_06_selng_amt",
        "06-11시": "tmzon_06_11_selng_amt",
        "11-14시": "tmzon_11_14_selng_amt",
        "14-17시": "tmzon_14_17_selng_amt",
        "17-21시": "tmzon_17_21_selng_amt",
        "21-24시": "tmzon_21_24_selng_amt",
    }

    value_columns = list(columns.values())
    result["time_sales_total"] = result[value_columns].sum(axis=1)

    for label, column in columns.items():
        result[f"time_pct_{label}"] = np.where(
            result["time_sales_total"] > 0,
            result[column] / result["time_sales_total"] * 100,
            np.nan,
        )

    reverse_map = {v: k for k, v in columns.items()}
    peak_column = result[value_columns].idxmax(axis=1)
    result["peak_time"] = peak_column.map(reverse_map)

    return result


def calculate_day_patterns(df: pd.DataFrame) -> pd.DataFrame:
    """요일별 비중, 평균 대비 증감률, 피크 요일을 계산한다."""
    result = df.copy()

    columns = {
        "월요일": "mon_selng_amt",
        "화요일": "tues_selng_amt",
        "수요일": "wed_selng_amt",
        "목요일": "thur_selng_amt",
        "금요일": "fri_selng_amt",
        "토요일": "sat_selng_amt",
        "일요일": "sun_selng_amt",
    }

    value_columns = list(columns.values())
    result["weekly_sales_total"] = result[value_columns].sum(axis=1)
    result["average_daily_sales"] = result["weekly_sales_total"] / 7

    for label, column in columns.items():
        result[f"day_pct_{label}"] = np.where(
            result["weekly_sales_total"] > 0,
            result[column] / result["weekly_sales_total"] * 100,
            np.nan,
        )

        result[f"day_diff_{label}"] = np.where(
            result["average_daily_sales"] > 0,
            (
                result[column] - result["average_daily_sales"]
            )
            / result["average_daily_sales"]
            * 100,
            np.nan,
        )

    reverse_map = {v: k for k, v in columns.items()}
    peak_column = result[value_columns].idxmax(axis=1)
    result["peak_day"] = peak_column.map(reverse_map)

    return result


def calculate_age_patterns(df: pd.DataFrame) -> pd.DataFrame:
    """연령대별 매출 비중과 주요 연령층을 계산한다."""
    result = df.copy()

    columns = {
        "10대": "agrde_10_selng_amt",
        "20대": "agrde_20_selng_amt",
        "30대": "agrde_30_selng_amt",
        "40대": "agrde_40_selng_amt",
        "50대": "agrde_50_selng_amt",
        "60대 이상": "agrde_60_above_selng_amt",
    }

    value_columns = list(columns.values())
    result["age_sales_total"] = result[value_columns].sum(axis=1)

    for label, column in columns.items():
        result[f"age_pct_{label}"] = np.where(
            result["age_sales_total"] > 0,
            result[column] / result["age_sales_total"] * 100,
            np.nan,
        )

    reverse_map = {v: k for k, v in columns.items()}
    primary_column = result[value_columns].idxmax(axis=1)
    result["primary_age"] = primary_column.map(reverse_map)

    return result


def calculate_gender_patterns(df: pd.DataFrame) -> pd.DataFrame:
    """남녀 매출 비중과 주요 성별을 계산한다."""
    result = df.copy()

    gender_total = result["ml_selng_amt"] + result["fml_selng_amt"]

    result["male_share"] = np.where(
        gender_total > 0,
        result["ml_selng_amt"] / gender_total * 100,
        np.nan,
    )

    result["female_share"] = np.where(
        gender_total > 0,
        result["fml_selng_amt"] / gender_total * 100,
        np.nan,
    )

    result["dominant_gender"] = np.select(
        [
            result["female_share"] > result["male_share"],
            result["male_share"] > result["female_share"],
        ],
        ["female", "male"],
        default="same",
    )

    return result


def build_metric_dataset(raw_df: pd.DataFrame) -> pd.DataFrame:
    """핵심 상권 지표 데이터셋을 만드는 예시 파이프라인."""
    metrics = aggregate_sales(raw_df)
    metrics = add_qoq_growth(metrics)

    store_metrics = raw_df[
        GROUP_KEYS + ["similr_induty_stor_co", "clsbiz_rt"]
    ].drop_duplicates(GROUP_KEYS)
    store_metrics = store_metrics.rename(
        columns={
            "similr_induty_stor_co": "store_count",
            "clsbiz_rt": "closing_rate",
        }
    )
    metrics = metrics.merge(store_metrics, on=GROUP_KEYS, how="left")
    metrics["demand_per_store"] = np.where(
        metrics["store_count"] > 0,
        metrics["transaction_count"] / metrics["store_count"],
        np.nan,
    )

    metrics["growth_score"] = (
        metrics.groupby(COMPARE_KEYS)["growth_rate"]
        .transform(growth_score)
    )

    metrics["transaction_score"] = (
        metrics.groupby(COMPARE_KEYS)["transaction_count"]
        .transform(transaction_score)
    )

    metrics["store_count_score"] = (
        metrics.groupby(COMPARE_KEYS)["store_count"]
        .transform(store_count_score)
    )

    metrics["demand_per_store_score"] = (
        metrics.groupby(COMPARE_KEYS)["demand_per_store"]
        .transform(demand_per_store_score)
    )

    metrics["closing_rate_score"] = (
        metrics.groupby(COMPARE_KEYS)["closing_rate"]
        .transform(closing_rate_score)
    )

    metrics["competition_score"] = competition_score(
        metrics["store_count_score"],
        metrics["demand_per_store_score"],
        metrics["closing_rate_score"],
    )

    metrics["exploration_score"] = exploration_score(
        metrics["growth_score"],
        metrics["transaction_score"],
        metrics["competition_score"],
    )

    metrics = add_percentile_and_rank(
        metrics, "sales", "sales"
    )
    metrics = add_percentile_and_rank(
        metrics, "transaction_count", "volume"
    )
    metrics = add_percentile_and_rank(
        metrics, "growth_rate", "growth"
    )
    metrics = add_percentile_and_rank(
        metrics, "competition_score", "competition"
    )
    metrics = add_seoul_rank(metrics)
    metrics = add_percentile_and_rank(
        metrics, "exploration_score", "exploration"
    )

    return metrics


```

## Python 구현 시 주의사항

1. `stdr_yyqu_cd`가 문자열 정렬만으로 시간 순서가 보장되는 형식인지 확인해야 한다.
2. 전분기 데이터가 실제로 바로 이전 분기인지 검증하는 로직이 있으면 더 안전하다.
3. 정규화 대상이 1개뿐이거나 모든 값이 동일한 경우 중립값 50점을 사용하는 정책을 적용할 수 있다.
4. 결측값을 0점으로 자동 변환하지 않는다. 데이터 없음과 낮은 점수는 다른 의미다.
5. `DemandPerStore`는 `StoreCount`가 0이면 산출하지 않는다.
6. `CompetitionScore`의 세 구성요소 중 하나라도 산출할 수 없으면 점수를 `NULL`로 처리한다.
7. `CompetitionScore`는 동일 분기·동일 업종 내 상대 비교 점수이며, 실제 경쟁 업체의 질·브랜드력·임대료까지 포함하는 직접 경쟁도는 아니다.

# 14. 핵심 산식 Quick Reference

| 지표                | 핵심 산식                                                  | 방향                                   |
| ------------------- | ---------------------------------------------------------- | -------------------------------------- |
| Sales               | `thsmon_selng_amt`                                         | 클수록 분기 매출 규모 큼               |
| Transaction         | `thsmon_selng_co`                                          | 클수록 분기 거래 규모 큼               |
| GrowthRate          | `(Sales_t - Sales_t-1) / Sales_t-1 × 100`                  | 클수록 성장                            |
| TransactionGrowth   | `(T_t - T_t-1) / T_t-1 × 100`                              | 클수록 거래 증가                       |
| GrowthScore         | `100 × (clip(G,P5,P95)-P5)/(P95-P5)`                       | 높을수록 긍정적                        |
| TransactionScore    | `100 × [ln(1+T)-ln(1+Tmin)]/[ln(1+Tmax)-ln(1+Tmin)]`       | 높을수록 긍정적                        |
| StoreCountScore     | `(1 - Norm(StoreCount)) × 100`                             | 높을수록 점포 공급이 적음              |
| DemandPerStore      | `TransactionCount / StoreCount`                            | 높을수록 점포당 수요가 많음            |
| DemandPerStoreScore | `Norm(DemandPerStore) × 100`                               | 높을수록 긍정적                        |
| ClosingRateScore    | `(1 - Norm(ClosingRate)) × 100`                            | 높을수록 폐업률이 낮음                 |
| CompetitionScore    | `0.50 StoreCount + 0.30 DemandPerStore + 0.20 ClosingRate` | 높을수록 경쟁 여건이 상대적으로 긍정적 |
| ExplorationScore    | `0.40 Growth + 0.35 Transaction + 0.25 CompetitionScore`   | 높을수록 탐색 우선                     |
| TimeShare           | `TimeSales_h / ΣTimeSales × 100`                           | 시간대 비중                            |
| PeakTime            | `argmax(TimeSales_h)`                                      | 최대 시간대                            |
| DayShare            | `DaySales_d / ΣDaySales × 100`                             | 요일 비중                              |
| DayDiff             | `(DaySales_d - DailyAvg) / DailyAvg × 100`                 | 평균 대비 증감                         |
| PeakDay             | `argmax(DaySales_d)`                                       | 최대 요일                              |
| AgeShare            | `AgeSales_a / ΣAgeSales × 100`                             | 연령 비중                              |
| PrimaryAge          | `argmax(AgeSales_a)`                                       | 주요 연령층                            |
| MaleShare           | `Male / (Male+Female) × 100`                               | 남성 비중                              |
| FemaleShare         | `Female / (Male+Female) × 100`                             | 여성 비중                              |

## 최종 정리

현재 PostgreSQL `sales_data`와 `store_data`를 이용해 다음 핵심 기능은 구현 가능하다.

- 매출 규모
- 거래 규모
- QoQ 매출 성장률
- QoQ 거래 성장률
- 성장 점수
- 거래 활성도 점수
- 동일 업종 점포 수
- 점포 증감
- 점포당 거래건수
- 폐업률 기반 CompetitionScore
- 최종 Exploration Score
- 매출/거래/성장/점수 순위 및 percentile
- 시간대/요일/연령/성별 소비 패턴

현재 데이터만으로 구현할 수 없는 값은 다음과 같다.

- 실제 동일 업종 경쟁 업체 수
- 연령×성별 교차 집단 비율

따라서 서비스에서는 **점포 수·점포당 거래건수·폐업률 기반의 CompetitionScore를 사용하고, 실제 경쟁 업체의 질이나 규모까지 포함하는 직접 경쟁도는 아니라는 점을 명확히 표기**한다.
